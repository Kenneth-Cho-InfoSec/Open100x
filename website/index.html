A longer reach, made in software

The repository describes stock camera apps that hide or limit extreme zoom controls. Open100x gives Android still photographers a native-zoom-plus-crop workflow with on-device image processing.

It uses the camera’s available native range first, then applies digital crop toward a requested scale up to 100×. The native maximum depends on the phone and selected lens.

Framing you can set

Choose a zoom preset or move along the zoom rail. The preview and saved capture follow the selected crop when the requested scale exceeds the camera’s native range.

A steadier high-zoom shot

A gyroscope-based steadiness indicator helps show movement. At high zoom, capture can wait briefly for a stable frame, then continue after its timeout.

Controls that follow hardware

Grid overlays, a histogram and manual exposure, white balance or focus controls are available where the selected camera supports them.

Capture stays on the phone

The checked-in manifest requests camera access and does not declare internet access. Optional resize-based smoothing and detail sharpening run locally before the image is saved.

The browser viewfinder at left demonstrates image cropping only. It does not connect to a phone camera, reproduce the app interface or predict final detail.

How the image moves

The app uses CameraX for preview, still capture and frame analysis. Camera2Interop passes supported camera options through the selected camera pipeline.

  1. CameraX pipelinePreview, still capture and low-resolution frame analysis.
  2. Native zoom plus cropCamera2Interop passes supported options; digital crop covers the requested remainder. CameraX reports a maximum based on device capability.
  3. Settled captureMotion readings can delay high-zoom capture until the frame steadies or times out.
  4. Local processing and saveOptional post-processing runs before MediaStore writes JPEG or WEBP to Pictures/Open100x.

Source paths: MainActivity, ProCameraController, AntiShakeController, ExtremeZoomPostProcessor, and the app manifest.

Take your first shot

Use the latest release on an Android 10+ phone with a camera. Lens range, manual settings and stabilization depend on the device.

  1. Install the current release. Open Latest releases, download the APK, and install it. Android may ask you to allow the app you used to download the file to install apps.
  2. Allow camera access. Open Open100x and grant its camera permission when Android asks. The inspected manifest declares the camera permission only.
  3. Set the frame. Choose a zoom preset or move the zoom control. Start lower, then raise the scale until the subject fits the viewfinder.
  4. Hold and capture. At higher zoom, brace the phone and watch the steadiness indicator. Use the shutter; if settling is enabled, the app may wait briefly before capture.
  5. Find the image. Open your gallery or file browser and look under Pictures/Open100x. The selected output format is JPEG or WEBP.

If the result looks different from the preview

The selected lens’s native zoom, focus and stabilization vary by phone. Digital crop enlarges fewer source pixels and cannot recover detail the camera did not capture. Try a lower zoom, better light, a supported telephoto lens or a steadier hold.

Build and inspect

Open100x is an Android application written in Kotlin. The checked-in project targets Android API 35, supports API 29 and later, and uses Kotlin/JVM 17 with CameraX 1.4.1.

Build from source

With a JDK and Android SDK configured, build the debug app from the repository root:

# Clone the public repository
git clone https://github.com/Kenneth-Cho-InfoSec/Open100x.git
cd Open100x

# Assemble the debug APK
./gradlew assembleDebug

The Gradle output is under app/build/outputs/apk/debug/. A connected test device can receive the APK with adb install app/build/outputs/apk/debug/app-debug.apk. The repository’s current Android CI workflow assembles a debug APK.

Configuration and data

There is no documented command-line interface, SDK, environment-variable configuration or remote service. Camera options are selected in the app and depend on the hardware’s reported capabilities. Captures are written through Android MediaStore; supported output formats are JPEG and WEBP.

The current source manifest declares CAMERA and not INTERNET. Image capture, post-processing and saving are implemented on-device. Review permission and storage behavior in app/src/main/AndroidManifest.xml, MainActivity and ExtremeZoomPostProcessor when updating the app.

Limits and troubleshooting

  • Zoom stops below 100×: the value is a requested hybrid framing target, not optical magnification. Camera support and selected lens affect the native portion; the remaining crop is digital.
  • Manual controls are unavailable: the app queries each camera’s capabilities. Switch lenses or use the controls the device reports.
  • No image appears: check camera permission, finish the capture, then look in Pictures/Open100x. Check free storage and report reproducible issues on GitHub.
  • Build fails: confirm JDK 17 and Android SDK configuration, accept required SDK licenses, then review the Gradle output.

For development, start with the source and issue tracker. No separate contribution guide was present at the repository root when this site was prepared.

Development and contributions

Before proposing a camera change, describe the phone, Android version, selected lens and requested scale that reproduce it. Build with ./gradlew assembleDebug. The project README says not to commit signing keys, keystore.properties, local.properties, Gradle caches or generated build output. Avoid attaching private photographs to public issues.

What the app does not promise

100× is a framing target

It is a requested combination of device-native zoom and digital crop. It does not mean 100× optical zoom, equal results across phones or a guaranteed amount of resolved detail.

Camera controls vary by device

Native zoom, autofocus, lens choice, stabilization, histogram and manual settings depend on the selected camera and its reported capabilities.

Enhancement is local image processing

The post-processor applies resize-based smoothing and contrast or detail sharpening, with optional upscaling capped at 24 megapixels. It is not an AI reconstruction model.

The inspected workflow is still photography

This site documents still capture. It makes no claim about video, RAW output or a measured image-quality result.

Common questions

Does 100× mean optical zoom? No. It is a requested hybrid framing scale that combines available native zoom with a digital crop.

Will every phone reach the same result? No. Camera hardware and selected lens determine native zoom, focus and available controls; digital crop cannot add captured detail.

Does Open100x record video? This site documents the still-capture flow in the inspected source. It does not claim video support.

Where do captures go? The app writes to Android MediaStore under Pictures/Open100x in JPEG or WEBP format.

Does it need an account or server? The checked-in manifest declares camera access and no internet permission; no remote service is documented in the inspected capture workflow.

What does post-processing do? It applies local resize-based smoothing and sharpening, with optional upscaling capped at 24 megapixels. It does not use AI reconstruction.

Which Android version is required? Android 10 / API 29 or later, according to the app’s minimum SDK.

Where can I report an issue? Use the GitHub issue tracker and include the Android version and camera or lens involved.
